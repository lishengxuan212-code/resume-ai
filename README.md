# 简历优化器

这是一个黑色 OFFER 首页与本地简历处理服务。用户上传文字型 PDF 或 DOCX 后，可核对提取的事实、选择目标岗位，先获得所有确实影响表达的必要事实问题和建议表达，再调用已配置的模型服务生成来源和方法论规则均可追溯的简历内容，并下载固定中文模板的 PDF。

页面中的材料和生成结果只保留在浏览器内存中，刷新页面会清空。服务端在请求处理期间使用内存上传和内存 PDF 缓冲，不提供账号、历史记录或持久化存储。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm ci
cp .env.example .env
```

在 `.env` 选择并配置**一家**服务商：设置 `AI_PROVIDER` 为 `openai`、`deepseek` 或 `qwen`，再填写该服务商对应的 key 和 model。例如选择 OpenAI 时填写 `OPENAI_API_KEY` 与 `OPENAI_MODEL`；选择 DeepSeek 或通义千问时填写各自的 `*_API_KEY` 与 `*_MODEL`。

```sh
npm run dev:full
```

该命令同时启动 Vite 页面和本地 Node API 服务；其中 `server:dev` 会通过 `--env-file=.env` 读取刚才创建的配置，开发时 Vite 会把 `/api` 转发给本地 Node 服务。供应商密钥只存在于 Node 服务的环境变量中，浏览器代码不会读取它们。不要把密钥提交到 Git，也不要将密钥粘贴到聊天、Issue 或截图中。

生产环境应由部署平台安全地注入同一组环境变量，并运行不读取本地文件的通用服务命令：

```sh
npm run server
```

## 当前功能与边界

- 支持文字型 PDF 和 DOCX；单文件最大 10 MB，PDF 最多 10 页。
- 扫描型或没有可提取文字的 PDF 暂不支持；用户可改用带文字的文件或在线填写。
- 上传后先核对事实和来源片段，再进行材料诊断。所有确实影响表达的独立问题都会显示并可全部跳过；为防止模型重复失控，程序安全上限为 12 个。回答会成为新的用户确认来源。
- 当前执行方法论版本为 `0.1`。每条生成内容必须携带来源 ID 和实际采用的规则 ID；服务端检查来源、规则、新增数字、条目组织/日期及改写相似度。过度照抄会自动返工一次。
- 支持 OpenAI、DeepSeek、通义千问三家服务商，运行时只启用其中一家。生成成功与否取决于该服务的可用性及本地配置。
- PDF 采用固定中文模板导出，响应以附件方式下载。
- 账号、持久化存储、OCR、后台队列和尚未覆盖代表性真实简历的系统化质量评估未实现；现有相似度检查只用于识别“优化结果几乎等于原文”，不能替代人工事实核对。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /api/config` | 返回当前服务商、模型和是否完成配置，不返回密钥。 |
| `POST /api/extract` | 接收 `resume` 文件字段，提取可核对的事实与来源片段。 |
| `POST /api/diagnose` | 接收确认后的事实、目标岗位和可选 JD，返回方法论诊断、所有必要问题及逐题建议表达。 |
| `POST /api/optimize` | 接收确认后的事实、可选回答或跳过标记，返回通过来源、规则和改写质量校验的简历内容。 |
| `POST /api/export` | 接收确认后的事实与优化结果，返回 PDF 附件。 |

## 校验、构建与部署

```sh
npm test
npm run build
npm run test:sites
```

`npm test` 运行服务端、客户端状态和无密钥 DOCX→优化→PDF 回归测试；模型服务在该回归中由注入的假服务替代，因此不会使用真实 key 或网络。`npm run build` 生成 Vite/Sites 所需产物。`npm run test:sites` 只验证静态 Sites Worker 的打包行为。

Vite 和 Worker 的静态托管无法运行 Node 的文档识别、模型调用或 PDF 服务。生产环境必须部署独立的 Node 进程，并通过同域部署或正确的反向代理为前端提供 `/api`；不能只发布 `dist/client` 后期待这些接口可用。

## AI 生成故障排查

每次供应商请求的完整响应时限默认是 120 秒，可通过服务端 `AI_TIMEOUT_MS` 设置为 1000–300000 毫秒。旧的 30 秒配置会在长简历尚未生成完时中止请求；修改现有 `.env` 后需重启后端。DeepSeek 的结构化简历编辑请求显式设置 `thinking.type=disabled`，避免模型别名默认思考模式增加等待；该选项不会发送给其他供应商。网络、超时和格式校验失败仍使用不同的固定提示。

识别、诊断、优化和 PDF 导出时显示居中等待蒙层、真实等待秒数、轮换鼓励语和可暂停的原创像素闯关动画。动画没有绑定虚构的后端进度；成功或失败才退出蒙层，错误时保留当前材料。

`node --env-file=.env scripts/check-ai-latency.mjs` 可对配置的供应商进行真实生成与导出验证（仅使用脚本中的虚构材料，会产生服务商调用）。`--baseline` 复现旧的 30 秒时限与默认思考参数，`--long` 使用较长材料。此脚本不属于日常自动化测试。

`/api/config` 中的 `configured: true` 只表示已经填写密钥和模型，不代表后端可以连接服务商或模型调用已经成功。页面可正常打开、文件可正常提取，也不能证明后端有外网访问权限。

生成失败时，后端保留 `provider_failed` 错误码，并使用固定中文提示区分联网权限拒绝、网络异常、密钥验证失败、余额不足、模型或接口配置、限流、超时以及结果结构不合格。结构校验失败时会携带明确约束自动完整重生成一次，第二次仍失败才提示用户；不会向浏览器转发上游错误原文、密钥或完整模型回复。已配置多个供应商时仍按原顺序尝试备用服务；全部失败时返回最后一次失败的安全提示。

方法论规则 ID（如 `D02`、`E03`、`F03`）只用于服务端选择规则、校验结果和问题追踪。接口结果仍保留这些 ID，但诊断页和优化结果页不向普通用户展示内部代码。

生成结果中的每条具体经历都使用独立的 `title + text` 结构：标题先概括候选人做了什么，正文再说明对象、行动、方法和有依据的结果。标题与正文同时进入服务端校验和 PDF 导出；缺少标题、标题为空、标题含无来源数字或任何用户可见文字包含内部规则代码时，结果会被拒绝并触发自动重生成。

最终优化结果不再使用窄弹窗，改为与材料核对页一致的宽版全页工作区，包括相同的顶部导航、页面导语、左侧目录、分区内容和移动端响应方式。结果页按照基本资料、个人概述、简历模块和简历提醒组织；每个目录模块都有编辑入口，进入的是同一个全局编辑状态，无需回到页面顶部。简历提醒只用于当前核对，不进入 PDF 正式简历。

诊断与生成现在是闭环链路：`POST /api/optimize` 会接收并重新校验上一阶段的诊断发现与问题，再把它们和用户回答一起交给生成模型。模型必须逐条处理诊断；如果用户跳过了与百分比口径相关的问题，服务端禁止歧义百分比原样进入结果，只允许省略数字或使用保守事实表述。个人概述必须由下方真实任务或成果支撑，不能继续堆叠空泛能力标签。

技能模块名称固定为“技能”，不显示“专业技能”“专业能力”或“技能清单”，也不为技能条目显示“经历 01”。技能没有“商业化运营”“用户运营”“产品运营”“工具”等上层类别，每条直接以“小标题：正文”单行展示，例如“付费与活动玩法：具备付费卡点设计、会员体系设计、商品结构规划、抽奖/盲盒/礼包活动设计和活动复盘经验。”小标题必须说明具体能力场景，不能使用“常用工具”“工具使用”“工具能力”等泛化标签；工具类内容可写成“原型与数据处理”。企业内部 AI 工具、自研数据看板等内部工具默认不进入投递稿；“精通”“熟练”等熟练度只有在来源或用户回答明确支持时才允许出现。

简历生成在一次浏览器请求内最多执行 3 次尝试：首次生成失败或结果未通过结构/改写质量校验时，服务端自动重试最多 2 次，并把失败原因作为修订要求交给下一次生成。整个过程不结束请求，前端保持同一个 loading 蒙层；三次均失败后才返回明确错误并保留材料。

诊断不仅指出问题，还要为事实不清或用户不会表达的内容提供一条基于已有事实的保守改写建议，让用户在生成前一键采用或修改确认。AI 可以删除无关、重复和事实口径不清的原文，也可以对已确认事实进行取舍、拆分和专业改写；不能替用户猜测数字口径、职责边界或不存在的成果。若现有事实不足以支撑改写，应建议删除模糊表述。

最终结果页的单条工作内容不使用卡片框，只保留编号、加粗标题、正文和条目间的轻分隔。用户可切换到编辑状态，直接修改个人概述、模块名称、经历信息、条目标题和正文；下载请求使用当前编辑后的结果，不需要返回材料页或再次调用 AI。

在受限的开发工具环境中启动服务，可能使 Node 进程无法访问外部 AI 接口。遇到 `EACCES`/`EPERM` 时，需要按环境的授权流程重新启动允许联网的后端；仅刷新网页或重新填写密钥不能解除该限制。排查时使用虚构材料，通过实际 `/api/optimize` 调用确认成功，并单独记录验证结果。

## 主要文件

- `src/App.jsx`：首页、上传、事实核对、诊断、优化和下载流程。
- `src/DiagnosisPage.jsx`：方法论诊断、有限追问和跳过后直接优化。
- `src/ResultPage.jsx`：与材料核对页一致的全页优化结果，展示每条经历的标题—内容层级。
- `src/ReviewPage.jsx`：宽版材料核对页，来源原文集中展示，字段不再要求手动选择来源。
- `src/ReadableEditor.jsx`：完整内容的分段展示和自动增高的原位编辑。
- `server/methodology/v0.1.js`：从方法论文档转成的 16 条可执行、稳定 ID 规则及 8 个验收场景。
- `server/`：Node API、文档提取、版本化提示组装、模型适配、结果与相似度校验、内存 PDF 导出。
- `tests/full-flow.test.mjs`：真实 DOCX 夹具、假模型服务与真实 PDF 导出的无密钥回归。
- `docs/selected-homepage.png`：已确认的首页视觉来源。
- `docs/AI与文档识别接入规划.md`：已实现能力和下一阶段事项。

字体采用 `@fontsource/noto-serif-sc`（OFL），图标采用 `@phosphor-icons/react`（MIT）。

材料核对页的浏览器回归位于 `tests/ui-review-regression.test.mjs`，需要可用的本地开发服务和 Playwright/Edge。`RESUME_TEST_URL` 可指定测试地址；未本地安装 Playwright 时，`PLAYWRIGHT_MODULE` 可指定现有运行时的 `playwright/index.mjs` 路径。此测试使用虚构材料和模拟模型响应，不消耗真实 AI 额度。
