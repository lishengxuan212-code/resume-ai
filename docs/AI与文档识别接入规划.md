# AI 与文档识别接入规划

版本：V0.1；本文同时记录已实现的首版能力和后续计划。

## 当前实现状态

以下能力已实现，且由仓库测试覆盖：

- Node/Express API 提供文字型 PDF 与 DOCX 的内存提取；单文件最大 10 MB，PDF 最多 10 页。
- 页面展示可编辑的事实与来源片段。优化结果的每条经历必须引用已确认的 `sourceIds`，服务端会验证结构和来源。
- 服务端可通过 `AI_PROVIDER` 在 OpenAI、DeepSeek、通义千问之间切换；密钥只从服务端环境变量读取，API 与浏览器均不返回密钥。
- 已确认的事实和优化结果可导出固定中文模板 PDF；PDF 在服务端内存中生成并作为下载附件返回。
- 无密钥端到端回归使用真实 DOCX 提取、真实结果校验和真实 PDF 导出，以及注入的假模型服务。该测试不调用真实模型网络。

以下项目尚未完成，仍属于后续计划：OCR、账号和权限、持久化、后台任务队列、文件生命周期清理、模型服务的真实质量评估，以及对真实用户密钥的成功调用验证。扫描型 PDF 当前会明确失败，不能视为已支持 OCR。

## 已落地的架构与边界

React/Vite 页面通过同源 `/api` 调用独立 Node 服务。Vite 开发服务器可代理请求；生产环境需要同域 Node 部署或正确的反向代理。静态 Vite/Worker 托管不能承载 Node 文档提取、模型调用和 PDF 导出。

当前没有账号或服务端持久化。上传文件通过 Multer 内存存储处理，PDF 使用内存缓冲生成；页面中的材料和结果只保留在浏览器内存，刷新即清空。该状态不等同于长期数据保留策略，后续若增加存储必须重新设计权限、保留期和删除机制。

当前真实接口如下：

| 接口 | 当前职责 |
| --- | --- |
| `GET /api/config` | 返回选中的服务商、模型和配置状态，不返回密钥。 |
| `POST /api/extract` | 接收单个 `resume` PDF/DOCX，返回可核对的事实与来源片段。 |
| `POST /api/optimize` | 接收确认后的事实和目标岗位，调用选中的模型服务并校验结果。 |
| `POST /api/export` | 校验事实与优化结果后返回固定模板 PDF。 |

## 文档处理现状

文字型 PDF 使用 PDF.js 提取页内文字，DOCX 使用 Mammoth 提取纯文本。DOCX 会形成文档来源块，PDF 来源块带页码。表格、多栏、艺术字体或复杂版式仍可能影响提取顺序，因此提取成功不代表事实无误，页面必须要求用户核对。

扫描型、无文字、损坏或加密文档不能作为完整事实继续处理。首版对扫描型 PDF 给出可读错误；OCR 或混合 PDF 回退尚未实现。

## AI 生成现状

配置值固定为 `openai`、`deepseek` 或 `qwen`，一次只启用一家。各服务商的 key 和模型名通过对应的服务端环境变量配置。未配置当前服务商时 API 返回可读的配置错误，页面会阻止开始优化。

生成内容是辅助草稿，不是事实认证。服务端会限制 JSON 结构、字符串长度和来源 ID，但无法仅凭结构校验判断职责归属、数字准确性或语义夸大。用户应在导出和投递前检查每一项事实。真实供应商的连接成功率、内容忠实度、耗时和成本尚未用用户密钥进行评估。

## 后续计划

### OCR 与复杂文档

为扫描和混合 PDF 设计按页 OCR、文字置信度、来源标记及成本控制；上线前使用授权样本覆盖空白页、多栏、表格、损坏和加密文件。不要以空文本或推测字段替代 OCR 结果。

### 账号、持久化与队列

若引入账号和历史版本，需增加访问控制、可撤销会话、过期与删除机制，并避免把完整简历写入普通日志。持久化任务、异步模型调用和多实例部署需要队列、幂等键、重试策略、状态恢复和成本限额；这些功能不能由当前内存 API 推断为已具备。

### 模型评估与安全

使用虚构或明确授权的中文样本比较三家服务商的来源一致性、表达质量、延迟、失败率和成本。模型输出、上传文件和招聘材料均是不可信输入，不能接受其中的指令来改变系统规则。真实密钥应只在部署环境保存，不能提交到 Git 或发送到聊天。
