# 首次开发边界

项目：在线 AI 简历修改网站

版本：V1.0

整理日期：2026-09-07

用途：记录本轮讨论确定的首版产品范围，作为后续需求细化和 AI 辅助开发的依据。

## 1. 产品定位与用户

面向国内实习和应届求职学生的免费 AI 简历优化网站。用户提供真实材料，系统承担专业判断、内容修改和排版，最终交付可投递的中文 PDF 简历。

同时服务两类用户：已有实习或项目经历但不会表达的学生，以及经历较少、不知道课程作业、竞赛、社团、志愿活动或兼职等素材如何用于简历的学生。按每段经历的信息缺口决定是否追问，不给用户固定分类。

首版面向国内求职，先做中文简历，暂不支持海外求职场景。前期不做商业化变现，通过小红书推广。

## 2. 专业分工与体验目标

- 全程由 AI 引导和处理，不依赖人工审核或人工修改服务。
- 用户负责提供真实信息、确认求职方向和核对事实。
- 系统负责经历取舍、表达优化、内容排序和排版。
- 不要求用户输入“更简洁”“突出贡献”等写作指令，不以开放式聊天作为主要操作方式。
- 用户修正事实后，由系统同步更新表达和成品。
- 基本材料提交完成后，目标为约 5 分钟完成首轮优化；不包含用户从零回忆和填写全部经历的时间。
- 首轮最多追问 3 个关键事实问题，允许跳过，不展开长时间经历访谈或完整职业规划。
- 缺少成果数据时基于已有事实表达，不编造职责、技能、经历或成绩。

## 3. 首版完整流程

1. **提交材料**：上传已有简历，或在线填写教育背景、经历和技能；提取内容后供用户核对。
2. **确认方向**：有目标的用户提供岗位名称或招聘要求；没有方向时，AI 结合经历和求职偏好推荐少量方向、解释依据，由用户确认。
3. **必要追问**：AI 判断关键缺口，只追问影响修改结果的事实，例如个人职责、具体行动和实际成果。
4. **生成成品**：AI 完成内容取舍、表达优化、排序和排版。
5. **核对事实**：用户检查事实是否准确；修正事实后，系统同步更新成品。缺失信息不得编造，不将“待补充”等占位内容带入最终投递版。
6. **下载与保存**：免费完成首次修改和 PDF 下载；需要长期保存、查看历史版本或跨设备继续时，引导注册登录。

## 4. 功能与覆盖范围

| 项目 | 首版边界 |
|---|---|
| 输入 | 上传现有简历，或在线填写简短表单 |
| 求职方向 | 支持指定岗位，也支持 AI 推荐方向、用户确认 |
| 修改交互 | 系统主动优化；用户补充和修正事实，无需指挥写作 |
| 排版 | 先采用一套简洁的中文模板，由系统自动排版 |
| 交付 | 可直接下载投递的 PDF 简历 |
| 设备 | 电脑操作为主，网页适配手机 |
| 账号 | 首次修改、下载免注册；保存历史和跨设备使用需登录 |
| 岗位 | 长期覆盖全部岗位；首版优先打磨运营、产品、技术、市场、电子信息、AI、财务、建筑 |
| 其他岗位 | 可采用通用修改流程，首版不承诺同等深度的专项优化 |

八个优先方向中包含岗位类别、行业和技术领域，后续可在内部细分。用户可直接输入岗位名称或粘贴招聘要求，无需先理解内部分类。

## 5. 方法论与后续迭代

用户已收集并提取一批简历修改视频的文字笔记，仍在整理，后续提供接入。

首版调用现有 AI 模型，将笔记整理为通用规则、岗位专项规则和信息不足时的追问规则，记录适用场景；有冲突的观点保留适用条件。真实上线前，用整理好的方法论和代表性案例检验修改质量。

模型训练不列入首版开发范围。后续结合真实用户反馈优化规则和案例库；用户简历不直接视为高质量训练样本。是否训练模型，待具备可靠质量评估和合适样本后再决定。

## 6. 开发与部署方式

由用户主导产品判断，借助 AI 开发。用户没有编程基础，也未独立开发过网站，部署经验来自 AI 教程或一键托管。

因此首版以托管部署、维护简单、操作步骤明确、问题便于定位为原则。具体服务商和技术配置在实施阶段结合预算确定。

先验证“真实材料输入 → AI 修改与事实核对 → 正常导出 PDF”的完整链路，再补齐历史版本、跨设备使用等功能。

## 7. 运行预算与成本控制

月度运行预算上限按 **1,000 元人民币**规划。

| 用途 | 月度预算 |
|---|---:|
| AI 调用：信息分析、岗位推荐、追问和改写 | 600 元 |
| 网站托管、数据库、文件存储等 | 200 元 |
| 流量波动、失败重试等预留 | 200 元 |
| 合计 | 1,000 元 |

以上为支出上限规划，不是服务商报价，也不代表已经验证的实际成本。能服务多少人，需要通过真实简历测试，测出完成一份简历的平均成本后估算。

开发中加入调用额度、频率限制和费用预警；复用已分析的信息，避免每次修改都重新处理整份简历。游客额度提前说明，保留首次完整修改和下载体验，避免用户完成填写后才遇到未告知的注册门槛。

## 8. 上线前验证重点

| 维度 | 验证内容 |
|---|---|
| 真实性 | 没有编造职责、技能或成果数据；用户可确认和修正事实 |
| 修改质量 | 内容更清楚、更贴合已确认的岗位，学生能在面试中解释 |
| 完成效率 | 追问足够少，用户能顺利完成并下载；检验约 5 分钟目标 |
| 交付质量 | PDF 无截断、错位等排版问题 |
| 运行成本 | 能记录单份简历的生成成本，检查预算与额度控制效果 |

前期重点观察完成修改并下载的比例，以及用户是否认为结果有帮助；注册量作为辅助指标。

## 9. 暂不纳入首版

- 海外求职和英文简历。
- 长时间深度访谈和完整职业规划。
- 依赖用户输入专业修改指令的开放式编辑流程。
- 人工审核或人工简历修改服务。
- 多套复杂模板和自由排版编辑器。
- 商业化收费和自有模型训练。

本文件记录首次开发边界，不代表已经完成开发、质量验证或部署。具体技术选型、文件格式支持范围和额度数值在后续实施方案中细化。
